# 最近组局、消息编号与基础防刷

## 最近组局

- `GET /api/pilot/squads/recent`，可选 `before` 游标，每页 10 条
- 仅返回当前身份参与过且仍为 ready / done 的队伍，未确认、取消、拒绝的队伍不作为聊天历史
- 只返回队友昵称、本局战场与时间等摘要，不返回他人凭证、手机号、独立反馈
- 发起新招募后仍可访问旧的已确认队伍聊天，聊天读写继续逐次校验成员身份
- “我的组局”底部提供折叠的“最近组局”入口，在弹窗中打开聊天
- 文字与语音仍保留 7 天，历史组局入口不延长消息保留期
- 新队伍出现时关闭历史聊天弹窗，避免遮住待确认队伍；切换身份会清除旧历史列表

## 消息编号

- `pilot_message_sequence` 持久记录消息编号上限，保留现有消息编号和语音地址
- 清理前先记录现有最大编号，发新消息时在同一 SQLite 事务内分配下一编号
- 清理全部旧消息、部分消息或重启后，编号仍递增，不会让旧客户端的 after 游标漏掉新消息
- 旧消息表无需重建，首次访问时自动初始化编号记录

## 基础防刷

持久化到 `pilot_rate_events`，按地址、规范化后的身份分别检查，原始地址不写入计数表。达到任一限制返回 HTTP 429、`detail.code=rate_limited` 与 `Retry-After` 秒数，前端显示具体等待时间。失败的业务尝试也计数，服务器重启不会清空配额；计数记录最长保留一小时。

| 操作 | 同地址 | 同身份 |
| --- | --- | --- |
| 匿名注册 | 20 次/分钟、120 次/小时 | — |
| 发布招募 | 30 次/分钟、300 次/小时 | 5 次/分钟、30 次/小时 |
| 申请组队 | 60 次/分钟 | 10 次/分钟 |
| 换一批 | 90 次/分钟 | 20 次/分钟 |
| 婉拒 | 60 次/分钟 | 10 次/分钟 |

确认、取消、局后反馈和正常状态/消息读取不受上述操作限流；聊天仍保留独立的每分钟 20 条发送限制。

阈值集中在 `app/services/pilot_limits.py`，无需新增环境变量。地址取 ASGI `request.client.host`，应用不自行信任用户提交的 X-Forwarded-For。代理部署需确保 ASGI 获取到真实且可信的客户端地址，否则共享地址的玩家会共用配额。本实现是基础频率限制，不用于证明游戏资料真实或抵御分布式机器人。

## 部署与检查

前后端一起部署，继续使用同一持久 SQLite 数据库和单实例配置。表结构在首次使用时自动补齐，保留旧数据。

后端：`.venv/bin/python -m unittest discover -s tests -q`
前端：`npm run build:h5`
