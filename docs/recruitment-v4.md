# 四步招募 v4

只借鉴 HTML 的产品流程、字段分组和联动，继续使用现有 Vue / FastAPI / SQLite，不复制其纯本地发布架构

## 发布流程

合作目的 → 地图与难度 → 自身配置 → 队友要求 → 预览 → 确认发布
草稿保存在当前浏览器，刷新恢复字段和步骤；昵称、游戏端、语言、语音方式和时段放在最后一步

## 双向判断

- 合作目的相同
- 地图和难度必须成对有交集，一张地图只选一种难度
- 33 任务至少有一项共同任务，确认页展示实际共同任务，不承诺完成未共同选择的任务
- 对方头盔 / 护甲 / 子弹分别达到我的最低门槛，反向同样检查；门槛不能高于自身对应装备
- 打法是 1–5 的激进程度，不代表能力；双方都落在对方接受区间，不限制区间必须低于自身
- 实力默认以自身分数 ±30%，允许自定义上下限，双向满足才匹配，不自动放宽
- 卡战备跑刀不展示和检查双方装备
- 区服、游戏端、语言、语音方式与开局时段继续作为共同条件

## 后端与兼容

- API 接受 schema_version=4，自动计算的实力分和默认范围均由服务端重算
- 组队提议持久保存实际共同地图、难度和任务，双方确认同一份约定
- v3 旧招募保留，但不和 v4 混合匹配，避免缺失的头盔 / 装备门槛被误认为满足
- 浏览器 pilot-preferences-v2 自动迁移 v1，未知头盔留空，不虚构；原 v1 资料保留
- 地图难度目录按本次产品蓝图配置，位于前端 recruitment-options.js 和后端 recruitment_rules.py；应按目标游戏版本维护
- 大厅、队列、名额保留、超时、聊天、语音和反馈继续使用原有服务

## 验证

后端 unittest 覆盖双向规则、边界、非法字段、混合版本、自动匹配和共同约定持久化
浏览器使用独立测试数据库验证四步发布、草稿恢复、候选筛选、双方确认与聊天
