# 招募分享、活动预约与运营数据

本次功能使用当前 Vue / FastAPI / SQLite 架构，不改变两人组队和双方确认规则

## 入口

- 导航下方「组队活动」：查看活动、预约或取消预约，设备当地时区显示时间
- 当前身份已发布公开招募并处于等待状态时显示「分享招募」
- 页面底部「运营管理」：输入运营密钥后查看数据、创建或取消活动
- 运营密钥来自后端 PILOT_METRICS_TOKEN，至少 32 字符，不能放入任何 VITE_ 环境变量
- 运营密钥仅保留在组件内存，关闭弹窗即清除，不写 localStorage
- 本地密钥已配置在正式后端 .env，线上需自行配置不同密钥

## 分享行为

链接格式为前端域名/#/?recruit=<随机32字符公开代码>，不包含玩家身份凭证

- 只允许分享当前版本的真实公开招募，测试身份不能创建分享
- 详情字段经过允许列表过滤，不包含手机号、游戏 ID、身份凭证、原始 KD、拒绝原因或反馈
- 对方需发布自己的条件，再申请组队；两人要求、在线状态、排队名额、排除名单与测试池隔离均在服务端检查
- 私密招募不可分享，招募过期、取消或被组队保留后，旧链接不再返回招募资料
- 离线招募可显示离线状态，不能申请；查看链接不会把发布者标记为在线
- 复制链接失败时可手动选择链接文字复制
- 本地 127.0.0.1 链接仅本机可访问，跨设备分享需部署到公网后使用公网域名
- 该版本链接在网站内打开详情，不生成社交平台的动态 Open Graph 预览图片

## 活动预约

- 运营选择区服、游戏端、语言、主要玩法；开始时间在 5 分钟至 30 天内
- 时长 30–240 分钟，容量 2–200 人，最多同时开放 20 场
- 预约独立于即时匹配，不发布招募，不预留队伍席位，也不自动替玩家确认
- 同一身份重复预约幂等，重叠活动不能重复预约
- 容量判断和预约写入在同一个 SQLite 写事务中，防止最后一个名额被多人占用
- 开场后玩家可把活动区服、游戏端、语言、玩法带入招募表单，自行核对地图、实力和队友条件
- 玩家已有活动招募时需先完成或取消，再切换活动条件
- 取消预约释放活动容量；运营取消后已预约者仍能看到取消状态
- 不发送短信、邮件或后台推送；需要玩家在开场时返回
- 只显示总人数及自己的预约状态，不公开预约者身份列表
- 匿名身份丢失会失去原预约的管理能力；当前不承诺跨设备恢复匿名预约

## 四项数据

仅运营密钥可读取 GET /api/pilot/operations/metrics

| 指标 | 分子 / 分母 |
| --- | --- |
| 访问到发布 | 新埋点开始后发布的独立身份 / 记录访问的独立身份 |
| 发布到双方确认 | 曾双方确认的招募数 / 该访问队列发布的招募数 |
| 反馈中实际游玩 | 自报已游玩的招募数 / 提交反馈的招募数 |
| 再次发布 | 发布至少两条招募的身份数 / 发布过招募的身份数 |

辅助指标：5 分钟内双方确认数、首次双方确认耗时中位数、反馈覆盖率、已游玩反馈中的再次组队意愿

口径：

- 访问按匿名身份去重，不能当成自然人数；清理存储或换设备可能重复
- 上线前已发布但后来才访问的招募，不混入新漏斗
- 无分母显示「—」，未反馈不算未游玩
- 测试身份及混入测试成员的组局排除
- 确认后取消仍计为曾确认，不回写历史以美化数据
- 重复发布只能说明再次使用，不能单独证明体验更好
- 目前为上线后累计统计，没有按渠道/活动归因、周留存或实验因果分析
