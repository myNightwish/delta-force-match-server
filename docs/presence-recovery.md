# 在线招募与匿名身份恢复

## 在线招募

- `participants.last_seen` 记录服务端确认的活动时间，75 秒内有活动视为在线
- 复用 `/api/pilot/state` 现有轮询刷新心跳，加入招募、读取候选与发出邀请也会刷新本人活动时间
- 浏览器切到后台时暂停状态、候选和聊天轮询，回到页面立即刷新
- 大厅、推荐、自动匹配都排除离线候选；邀请时在同一事务内重新检查双方在线状态，拦截陈旧卡片
- 离线暂时隐藏，不删除招募；回到页面恢复原招募与排队时间，原有 20 分钟有效期不延长
- 已确认队伍不因离线被解散，待确认队伍仍按原有 120 秒确认期限处理
- 旧数据库自动补 `last_seen` 列，旧记录初始离线，真实客户端回访后重新上线；不清空历史数据
- 关闭页面后最长约 75 秒才被判离线，这是容忍短时断网的宽限时间，并非瞬时退出

## 匿名身份恢复

- 未知匿名身份返回 HTTP 401，`detail.code=anonymous_identity_invalid`
- 客户端仅依据此明确错误自动重建匿名身份，保留本地表单草稿
- 多个失败请求共用一次恢复操作，晚到的恢复结果不能覆盖期间已切换的账号
- GET 读取恢复后重试一次，POST 邀请/确认/取消/反馈/发布等操作不自动重放，需用户重新操作
- 网络断开、503、普通 401/403、参数错误不会重建匿名身份
- 手机会话不套用匿名恢复规则，保留原有手机号登录过期处理
- 恢复只恢复页面可用性及本地资料，不能找回服务端已经丢失的历史记录

## 部署

前后端一起更新，无新增环境变量。`PILOT_DB=/var/data/pilot.db` 必须配合 Render Disks 中实际挂载到 `/var/data` 的持久磁盘；仅写环境变量不代表已挂载磁盘。继续保持单实例、单 worker。
